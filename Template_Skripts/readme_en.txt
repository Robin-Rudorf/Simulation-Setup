SAMoS workflow for free-boundary Active Vertex Model simulations

OVERVIEW
--------
This collection contains the scripts and configuration files used with SAMoS
(Soft Active Matter on Surfaces) to run and analyse free-boundary Active
Vertex Model simulations for the thesis Collective Motion and Structural
Relaxation in a Free-Boundary Active Vertex Model.

The workflow prepares initial tissue configurations, generates parameter
combinations, launches SAMoS runs, and collects analysis results. It also
includes utilities for time-series plots, structural-relaxation analysis, and
archiving.

The simulations share a common launch framework. The supplied configuration is
an example of the workflow, not a universal configuration for every thesis
result. To reproduce a figure, use its versions of both configuration files
and the corresponding analysis scripts and data.

1. REQUIREMENTS
---------------
The shell scripts are intended for a Linux environment with Bash and GNU
command-line utilities.

SAMoS executable available as samos
  Runs the simulations; SAMoS must be installed separately with support for
  the model features used in the configuration.

Python 3
  Runs the initialization, analysis, and plotting scripts.

NumPy, pandas, Matplotlib, SciPy, VTK
  Dependencies used by the supplied Python utilities and their imported
  modules.

bc, tar, gz
  Parameter calculations and unpacking the Python utilities.

GNU screen
  Required for the screen launchers to prevent the run from terminating when the SSH connection is disconnected. zip-runs.sh can also start a screen
  session when invoked directly over SSH.

7z
  Required for the archive scripts.

mail
  Required only when completion notifications are enabled; mail delivery must
  be configured separately.


2. FILES IN THE WORKFLOW
------------------------
Keep the launch scripts, configuration files, and utility archive together in
the working directory. Several scripts use relative paths and should be
launched from that directory.


Simulation and configuration
----------------------------

open_runs.sh
  Main launcher. Reads the sweep configuration, unpacks the utilities,
  prepares inputs and run directories, launches SAMoS processes, and collects
  analysis outputs.

open_runs.config
  Defines parameter values/ranges, the number of repeats and parallel
  processes, output frequency, analysis settings, and optional
  post-processing.

open_boundary_generic.conf
  SAMoS configuration template. Defines model interactions, alignment,
  boundary mechanics, integration settings, and output commands. The launcher
  replaces its @...@ placeholders for each run.

python_utils.tar.gz
  Archive of Python initialization, analysis, and plotting utilities. The
  current launcher extracts it at every start.

testparams.sh
  Displays configured parameters and checks selected prerequisites before
  a run. It does not replace checking the configuration itself.

Launching and reconnecting
--------------------------

start_screen.sh
  Starts open_runs.sh inside a GNU-screen session, allowing the run to
  continue after disconnecting from an SSH session.

start_screen_nice.sh
  Alternative launcher using nice -n 19 to give the process lower CPU
  scheduling priority.

restore_screen.sh
  Generated by a screen launcher. Reconnects to that run's screen session; it
  is not a restart mechanism for a terminated simulation.

The two screen launchers are alternatives. They are local process launchers,
not scheduler submission scripts such as SLURM jobs.

Additional plotting and archiving
---------------------------------

plot_time_series.py
  Produces general time-series plots from the CSV files in
  analyse/time_series/. Can be called automatically by the launcher.

sort_avg_plot.sh
  Splits and plots averaged results from analyse/avg_compute_order.csv.
  Retained as a separate, manually invoked utility. Adjust its grouping and
  plotting settings as needed.

plot_pickle_data.sh
  Converts saved pickle results into MSD and
  self-intermediate-scattering-function CSV files and plots. Edit its input,
  splitting, grouping, and plotting settings before use.

zip-runs.sh
  Creates and tests archives of analysis results and, depending on its
  invocation, the full working directory. Can be called automatically at the
  end of a run.

zip-analyse.sh
  Manually archives the analyse/ directory.

3. PYTHON UTILITIES
-------------------

Initialization and numerical analysis

generate_avm_ic.py
  Generates initial tissue and boundary input files.

compute_order.py
  Computes per-run order statistics and writes them alongside the run
  parameters.

save_time_series.py
  Saves order-parameter time series for subsequent analysis or plotting.

AnalyzeGlassy.py
  Entry point for structural-dynamics analysis, including MSD and the
  self-intermediate scattering function. The launcher invokes the separately
  configured AnalyzeGlassy command.

pickle2csv_art.py
  Extracts relaxation-time information from the pickle results using the
  configured scattering-function threshold.

co_art_join.py
  Combines order statistics and structural-relaxation results.

co_mean.py
  Produces parameter-grouped averages across repeated runs.

pickle2csv.py
  Exports time-dependent MSD and scattering-function data from pickle files.

Supporting modules
------------------

Glassy.py, Configuration.py, Geometry.py, CellList.py, Interaction.py,
Hessian.py, Tesselation.py, Writer.py, read_conf.py, read_param.py, and
read_data.py provide shared analysis, geometry, and input/output
functionality. They are imported by other utilities and should be retained
even if they are not launched directly.

Plotting and maintenance utilities
----------------------------------

plot_runs.py, color_plot_runs.py, plot_runs_multicolors.py, color_plot.py, and
plot_pickle_data.py provide general plotting functions. In particular,
sort_avg_plot.sh uses plot_runs.py and color_plot_runs.py, so these Python
files remain necessary when sort_plot.sh is omitted. The archive also contains
targz-utils.sh, a utility-archive maintenance helper.

The launcher unpacks python_utils.tar.gz at startup and can overwrite existing
utility files. If analysis code is changed, update the archived copy as well,
or deliberately change the launcher to use an unpacked utility directory.
Preserve the exact code version used for each analysis.

4. CONFIGURATION
----------------

Both configuration files are required to describe a simulation.
open_runs.config controls the scan and workflow; the open_boundary_generic.conf controls the model and integration setup.

parfile
  Filename of the SAMoS template.

CORES
  Number of parallel worker processes. Choose a value appropriate for the
  available computing resources.

cellcountval
  Requested cell counts used when generating initial configurations.

randomval
  Number of initial-condition realizations. One input is generated per cell
  count and repeat and reused across the parameter combinations.

infile, infile_bound
  Optional existing tissue/boundary inputs. With infile set, automatic
  generation is skipped, randomval is forced to 1, and the run metadata uses
  cc=0; the actual cell count comes from the input.

tauval
  Explicit alignment-control values. When non-empty, overrides the range
  defined by tau_start, tau_end, and tau_increment.

gamval, nuval, kval, permult, lineval, v0val
  Mechanical, noise, boundary, shape-control, and activity settings inserted
  into the template.

trun
  Number of integration steps.

freq
  Output interval in integration steps.

skip_cpo
  Number of saved frames skipped by the order-statistics analysis.

modval
  Controls translation subtraction in the archived compute_order.py: 0 retains
  the mean velocity; 1 subtracts it before computing order.

v_init, v_value
  Control whether initial velocities are set along the generated polarities
  and their magnitude.

skip
  Number of saved frames skipped by the structural analysis.

SelfIntLimit
  Scattering-function threshold passed to the relaxation-time extraction.

create_timeseries, create_pickle
  Enable saving order time series and running the structural-analysis stage,
  respectively.

plot_time_series, zip_runs
  Enable optional plotting and archiving after the runs.

del_samos_data
  If set to 1, deletes per-run .vtp, .dat, and .fc files after analysis. 
  Attention: if set to 0, multiple GByte of data will be generated.

fertig_mail
  Optional completion-notification address. Leave empty if notifications are
  not configured.

The name tau is a historical workflow label: its meaning depends on where
@TAU@ appears in the SAMoS template. With pair_align velocity { J = @TAU@; ...
}, tauval sets J directly. With external_align ajpolar or afpolar using tau =
@TAU@, it sets the response parameter tau; the thesis then uses J = 1/tau.
Check the selected template before interpreting directory names, CSV columns,
or plot axes.

The launcher uses Lambda = -2 * permult * Gamma. The configuration files
document the thesis mapping p0 = 2 * permult / sqrt(A0); permult is not itself
p0. The archived initial-condition generator defaults to A0 = 3.0.

The time step is specified in the SAMoS template. Simulation duration and
saved-frame spacing are trun * dt and freq * dt, respectively. Frame counts,
integration-step counts, and simulation time units should not be interchanged.

The repeat index rand is not the Brownian-integrator seed. The supplied
template versions fix that seed to 1, and the launcher does not pass a seed to
the initial-condition generator. Retain the generated inputs and document the
actual seed settings to identify and reproduce individual realizations.

5. RUNNING A SCAN

1. Make a separate working copy of the Tamplate_Skripts folder for the scan. Keep archived results outside
   this working directory.

2. Place the desired versions of both configuration files in that copy and
   check the analysis scripts.

3. Keep sort_plot='0' when omitting sort_plot.sh. Choose the desired
   parallelism, analysis options, and data-retention setting. Leave
   fertig_mail empty unless completion emails are configured.

4. Make the shell scripts executable and inspect the configured parameters:

    chmod +x *.py
    chmod +x *.sh
    ./testparams.sh

5. Start the workflow using one of the following alternatives:

    # Direct execution
    ./open_runs.sh

    # Alternatively, use a persistent screen session
    ./start_screen.sh

    # Or use screen with lower CPU scheduling priority
    ./start_screen_nice.sh

For a screen session, detach using Ctrl+A, then D. Reconnect while it is
running with:

    ./restore_screen.sh

List screen sessions with screen -ls. For live progress from a worker, use,
for example:

    tail -f analyse/Core_2.log

Data retention: the launcher refuses to start if samos_runs/ already exists.
Once this check is passed, it removes and recreates the analysis, input, and
worker-list directories. Do not remove only samos_runs/ and restart in a
directory containing results you want to preserve. Use a fresh working copy
instead. Set del_samos_data='0' if the raw simulation files are needed for
later analysis; with deletion enabled, do not assume they will be retained if
an analysis stage reports an error.

6. GENERATED OUTPUTS

input/
  Generated or copied initial tissue and boundary configurations.

list/
  Run-directory lists assigned to the parallel workers.

samos_runs/
  Individual simulation directories, nested by parameter values and repeat
  index.

analyse/compute_order.csv
  Per-run order statistics, with structural-analysis fields added when that
  stage is enabled.

analyse/compute_order.csv.cols.txt
  Description of the result columns.

analyse/avg_compute_order.csv
  Averages across repeats, generated when more than one repeat is configured.

analyse/time_series/
  Saved order-parameter time series and optional general plots. The launcher
  does not apply skip_cpo to these exports; select the evaluation window in
  the subsequent analysis.

analyse/pickle/
  Structural-analysis results when pickle generation is enabled.

analyse/alpha_relaxation_time.csv
  Extracted relaxation-time results.

analyse/pickle_plot/
  CSV exports and plots generated by plot_pickle_data.sh.

analyse/Samos_Log.txt, analyse/Samos_Errors.txt
  Combined workflow logs and error reports. The error file lists failed
  stages; consult Samos_Log.txt and the per-pickle logs for details.

analyse/Core_*.log
  Per-worker progress logs, removed when the normal simulation and analysis
  stage finishes.

The launcher also copies the scan configuration and SAMoS template into
analyse/. Archive scripts write their ZIP files into the parent directory of
the working folder. zip-runs.sh also writes an archive log there, ending in
_zip.Ok.log or _zip.Error.log when it finishes.

Check the error reports before using the outputs: the presence of a CSV or
plot alone does not establish that every simulation and analysis step
completed successfully.
